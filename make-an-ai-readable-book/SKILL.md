# 制作一本给 AI 阅读的书（EPUB → AI-Readable Book）

目标：把一本 EPUB 制作成**给 AI 阅读的书**——一个自描述的书本文件夹，任何 AI/Agent 拿到它后，从其中的 `SKILL.md` 进入，按"协议 → 全书 → 章 → 小节 → 段落"逐级下钻，按需定位内容，而不必通读全书。人类读者则从 `目录.md` 进入。

书与人读的书不一样：AI 不翻页，它靠**协议、摘要、关键词和路径**导航。所以这本书的每一层都有记录文件告诉 AI"这一层有什么、下一层去哪找"，段落原文永远放在最后一层、按需打开。

结构化环节全部由本技能的脚本完成（仅 Python 标准库，需 Python 3.8+）；AI 只做两件脚本做不了的事：撰写章节要点摘要、提炼检索关键词。

## 产出结构

```
<书库>/
├── SKILL.md              ← AI 入口：L0 元数据 + L1 阅读协议
├── 目录.md               ← L2：全书统计 + 章级导航 + AI 一句话导读（人类读者入口）
├── 索引.md               ← L2：关键词 → 小节直达表
├── _build_stats.json     ← 机器统计（make_skill.py 的数据源，勿删）
├── keywords.json         ← AI 阶段产出的关键词数据源
└── NN_章名/
    ├── 00_章节记录.md     ← L3：小节导航表 + AI 本章要点
    └── NN_小节名/
        ├── 00_小节记录.md ← L4：逐段导航（类型+40字摘录）+ frontmatter
        └── 段落_NNN.md    ← L5：原文，每文件一段
```

脚本位于本技能目录的 `scripts/` 下（下文命令中的 `scripts/` 均相对本技能目录）。所有脚本支持中文路径；Windows 控制台输出已按 UTF-8 处理。

## 工作流

### 第 1 步：目录预览（脚本）

```
python scripts/parse_epub.py --epub "<epub路径>"
```

打印书名、作者、目录来源（toc.ncx 或 nav.xhtml，自动识别）与完整章/小节层级。核对：一级条目是否是"章"级、小节归属是否合理。目录解析规则——EPUB2 用 toc.ncx，EPUB3 回退 nav.xhtml；超过 2 级的条目自动并入所属章。

### 第 2 步：标记体检（脚本，发现异常才需要行动）

```
python scripts/scan_tags.py --epub "<epub路径>"
```

统计全部 XHTML 的标签/样式清单。抽取器默认约定：h1/h2 为章/节标题、h3-h6 与 `p.p5` 为内部小标题、`p.fnote` 为脚注、`p.middle-img` 与 `div.pic` 为图片容器、其余 `<p>` 为正文。若本书明显使用其他样式类承担这些角色（例如小标题是 `p.nonindent`），先改 `scripts/epublib.py` 中 `Extractor._flush` 的样式映射，再继续——约定错了会把小标题当正文、把正文当脚注。

### 第 3 步：生成结构库（脚本）

```
python scripts/build_tree.py --epub "<epub路径>" [--out <输出目录>]
```

默认输出到 EPUB 同目录、以书名命名的文件夹。生成：章/小节/段落文件、三级记录文件、`目录.md`、`SKILL.md`（协议初版）、`_build_stats.json`。固定规则：部（Part）不设第四层；无小节的章建 `00_全文`；与首个小节不同文件的章题记建 `00_章首`；插图写 `[图: 文件名.jpg]` 占位符不导出图片。目录已存在时会清空重建。

### 第 4 步：校验（脚本，必须通过）

```
python scripts/validate.py --epub "<epub路径>" --out <书库目录>
```

逐段落与 EPUB 源比对 + 检查记录文件齐全与命名合法。**不通过必须修复重跑，禁止带着失败进入 AI 阶段。**

### 第 5 步：AI 增强（Agent 工作；书大时用子代理）

1. **章节摘要**：把各章分组（每组 ≤3 章或 ≤5 万字符）派并行子代理。每个子代理：Read 该章 `00_章节记录.md` 的小节导航表 → 按顺序 Read 该章全部 `段落_*.md`（含"章首/全文"小节）→ 用 Edit 把该章记录中占位行「> 待撰写：由 AI 阅读本章各小节后补写。」替换为真实摘要——2~3 句概述 + 逐小节要点（每条一行、含小节名）+ 3~6 个加粗核心概念，总量 400~800 字；子代理同时回传"章文件夹名｜一句话导读（30~60字）"。不得改动任何段落文件或小节记录。注意并发限制：一次派 2~3 个子代理，失败（如 concurrency limit）就等 60 秒串行重派。
2. **关键词**：通读各章摘要后，在书库根写 `keywords.json`——一级键 = 章文件夹名；每章 `chapter_keywords` 5~8 个、`sections` 以小节序号字符串（"0"、"1"…）为键、每节 3~7 个词。词取正文核心术语而非仅标题词（如"尼克止损""假突破"这类正文术语），中英文术语都可。
3. **元数据注入**：

```
python scripts/make_skill.py --out <书库目录>
```

自动读取书库内 `keywords.json`：给章/小节记录与 `目录.md` 注入 frontmatter（含 keywords）、重建 `索引.md`、把主题词追加进 `SKILL.md` 的 description。缺某节关键词会打警告，补数据后重跑即可（幂等）。

### 第 6 步：交付

复跑一次 `validate.py` 确认无回归；向用户呈现：最终目录树、章/小节/段落统计、各章一句话导读（来自第 5 步子代理回传），并说明 AI 从 `<书库>/SKILL.md` 进入、人类读者从 `目录.md` 进入。

## 常见坑

- **参考文献/附录是扫描图片**：段落文件只有 `[图: xxx.jpg]` 占位符、字数为 0，属正常现象，摘要中如实说明即可。
- **目录条目 ≠ 文件**：章条目与首个小节可能指向同一文件（锚点切分），`chapter_plan` 已处理（不重复建"章首"）。
- **中文控制台编码**：脚本内部已 `sys.stdout.reconfigure(encoding="utf-8")`，若外层管道仍乱码，设置环境变量 `PYTHONIOENCODING=utf-8`。
- **文件名清理**：章/小节名中的 `\ / : * ? " < > |` 会自动替换，Windows 保留字符冲突需人工检查。
- **书名生僻**：输出目录名取自 OPF 的 dc:title；`--out` 可强制指定。
